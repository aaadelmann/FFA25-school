The workshop uses \textbf{OPALX in a Docker container} for simulation and
\textbf{Python/Jupyter on your computer} for the School notebook and plots.
Install both before the workshop and complete the checks below. You do not
need to compile OPALX or install MPI locally. These instructions follow the
\href{https://opalx-project.github.io/opalx-manual/getting-started/index.html\#run-with-docker}{current OPALX Docker guide}.

\section{Install and start Docker}
\begin{itemize}
\item \textbf{macOS:} install
\href{https://docs.docker.com/desktop/setup/install/mac-install/}{Docker Desktop for Mac},
choosing Apple silicon or Intel to match your machine. Start Docker Desktop.
If a separate Docker client cannot find \texttt{docker-credential-desktop},
add the bundled tools to this terminal's path:
\begin{commands}
export PATH="/Applications/Docker.app/Contents/Resources/bin:$PATH"
\end{commands}
\item \textbf{Windows:} install
\href{https://docs.docker.com/desktop/setup/install/windows-install/}{Docker Desktop with the WSL 2 backend}
and enable its \href{https://docs.docker.com/desktop/features/wsl/}{Ubuntu WSL integration}.
Run all commands below in the \emph{Ubuntu/WSL terminal}, including Python
and Jupyter. Keep the course in your Linux home directory.
\item \textbf{Linux:} follow the
\href{https://docs.docker.com/engine/install/}{installation} and
\href{https://docs.docker.com/engine/install/linux-postinstall/}{post-installation instructions}
to run Docker as your normal user without \texttt{sudo}.
\end{itemize}

The remaining commands use Bash or Zsh: Terminal on macOS/Linux or Ubuntu
on Windows. Check that Docker can contact its running server:
\begin{commands}
docker version
docker run --rm hello-world
\end{commands}
The first command should show both Client and Server information; the second
should print a successful test message.

\section{Download the OPALX CPU image}
\begin{commands}
export OPALX_IMAGE=ghcr.io/opalx-project/opalx:cpu
docker pull "$OPALX_IMAGE"
docker run --rm "$OPALX_IMAGE" --version-full --info 5
docker run --rm "$OPALX_IMAGE" --help
\end{commands}
This public CPU/OpenMP image supports Linux AMD64 and ARM64; Docker selects
the architecture. No GitHub login is needed. To check the selected architecture:
\begin{commands}
docker run --rm --entrypoint uname "$OPALX_IMAGE" -m
\end{commands}
Expect \texttt{aarch64} on Apple silicon and \texttt{x86\_64} on Intel/AMD.
Do not force \texttt{linux/amd64} on an Apple silicon Mac. If necessary, run
\texttt{unset DOCKER\_DEFAULT\_PLATFORM}, then pull again.

The \texttt{cpu} tag follows successful development builds; it is not a fixed
release. Use the workshop image digest supplied by the organisers when available.
To select the exact image just downloaded:
\begin{commands}
export OPALX_IMAGE="$(docker image inspect \
  --format '{{index .RepoDigests 0}}' "$OPALX_IMAGE")"
printf '%s\n' "$OPALX_IMAGE"
\end{commands}

\section{Prepare the course and Python environment}
Obtain the workshop checkout or ZIP supplied by the organisers. It must contain
\path{opalx/FFA26_OPALX.ipynb}, \path{opalx/pyfiles/}, and the three machine
input directories. Keep this structure intact. In the commands below, replace
\path{/path/to/FFA25-school} with your course directory.
\begin{commands}
cd /path/to/FFA25-school
export FFA_SCHOOL="$(pwd -P)"
python3 --version
\end{commands}
Use \textbf{Python 3.10 or newer}. On macOS, install a current Python from
\href{https://www.python.org/downloads/macos/}{python.org} if needed. On
Ubuntu/WSL, the distribution packages \texttt{python3}, \texttt{python3-venv}
and \texttt{python3-pip} provide the starting environment; check the version.
Create a separate environment and install the notebook packages:
\begin{commands}
python3 -m venv "$HOME/.venv-ffa26"
source "$HOME/.venv-ffa26/bin/activate"
python -m pip install --upgrade pip
python -m pip install numpy pandas matplotlib h5py \
  jupyterlab ipykernel
\end{commands}
The Python environment runs locally, not inside the OPALX runtime container.
All commands in the next section use this same activated environment.

\section{Open the notebook and select Docker}
Start Jupyter from the activated Python environment:
\begin{commands}
cd "$FFA_SCHOOL/opalx"
python -m jupyterlab FFA26_OPALX.ipynb
\end{commands}
Open the displayed local URL and select the environment's Python kernel.
The notebook's first setup cell explicitly selects the simulation backend:
\begin{commands}
BACKEND = "docker"
IMAGE = "ghcr.io/opalx-project/opalx:cpu"
EXECUTABLE = None
\end{commands}
Leave these defaults for the workshop, or replace \texttt{IMAGE} with the
organisers' image reference. To select the image pinned in Section~2, paste
the printed digest reference into \texttt{IMAGE}. The notebook does not read
\texttt{OPALX\_IMAGE} or \texttt{OPALX\_EXE} from your shell.

Run the setup cell. It checks the Docker server and local image, displays the
backend, image digest, architecture, OPALX version and revision, and fixes the
image for this session. If Docker or the image is missing, it stops with an
error; it never switches to a local OPALX executable. Download the image first
with \texttt{docker pull}, then retry the setup cell.

No launcher script or host MPI setup is needed. The existing helper starts
Docker directly with one MPI rank and one OpenMP thread. It mounts the whole
course at the same absolute path inside the container, so local Python can
read the generated field maps and particle data. The run manifests record the
selected backend, image identity and actual command. Results persist after
the container exits.

\section{Run the three School lessons}
Run all cells from the top. Complete the original 16-cell ring before the
55-degree/D-off variant and then the fourfold ring. Each machine's input
supplies its validated numerical settings. The native COF report should show
a verified closed orbit, a stable one-turn eigenanalysis and full tunes.
For the unchanged 12 MeV original ring, expect approximately
$Q_r=3.41066$ and $Q_Y=3.39111$.

The notebook creates a fresh directory under \path{opalx/runs/}. Its new COF
JSON supplies the closed state and full tunes used for tracking; standalone
JSON snapshots are not loaded. Keep these generated results local. Restart
the kernel and run from the top when starting another experiment.

\subsection*{Returning later}
Start Docker, activate Python and open the notebook. No executable or launcher
exports are needed:
\begin{commands}
source "$HOME/.venv-ffa26/bin/activate"
cd /path/to/FFA25-school/opalx
python -m jupyterlab FFA26_OPALX.ipynb
\end{commands}
Keep the selected image reference in the notebook's setup cell. Pull a new
image only when you intend to update it; a running session keeps using its
original image.

\subsection*{Optional native mode}
For a locally installed OPALX build, edit the setup cell explicitly:
\begin{commands}
BACKEND = "native"
EXECUTABLE = "/absolute/path/to/opalx"
\end{commands}
The helper checks this executable and displays its version and revision.
Only native mode uses optional \texttt{OPALX\_LAUNCHER} or
\texttt{OPALX\_MPI\_FLAGS} settings. Return \texttt{BACKEND} to
\texttt{"docker"} for the workshop container.

\section{If a check fails}
\begin{itemize}
\item \textbf{Docker server unavailable:} start Docker Desktop or the Linux
Docker service, then repeat \texttt{docker version}.
\item \textbf{Mount denied or output path missing:} allow Docker Desktop to
share the course directory. Keep inputs and run directories inside the course
checkout so the helper can mount them together.
\item \textbf{Image unavailable:} check \texttt{IMAGE} in the setup cell and
run \texttt{docker pull} with that exact reference. Retry the setup cell. In
native mode, check the explicit \texttt{EXECUTABLE} path instead.
\item \textbf{Python imports fail:} activate the workshop environment, start
its Jupyter, and restart the notebook kernel.
\end{itemize}
For unresolved problems, retain the Docker image reference, the version/revision
output and the failing command or notebook \texttt{run.log}. Consult the
\href{https://opalx-project.github.io/opalx-manual/}{OPALX manual} or contact the
workshop organisers before the workshop.
